# Run: summarizer_20260925_073307 — v0.1.0 pilot (NEGATIVE RESULT, root-caused)

**What changed / why:** First summarizer SFT run on `summarizer_dataset_v1`
(224 silver examples, prompt/completion format, full FT) on the Colab T4
(466 s). Purpose: first summarizer proof-of-concept per brief step 9.

**Result: NEGATIVE.** On the frozen test split the fine-tuned model scored
ROUGE-L 0.095 with section-format compliance 0.024 — the untouched base
model scored 0.107 / 0.058 on the same prompts. The fine-tuned model did not
learn the sectioned summary format.

**Root cause (my bug, in `training/summarizer/train.py`):** the dataset
builder pre-tokenized the CONCATENATED prompt+completion string and removed
the text columns before handing the dataset to TRL's SFTTrainer. That
destroyed the prompt/completion boundary information, so
`completion_only_loss=True` could not mask the prompt — the model trained on
the full sequence (opportunity text included) instead of the summary.
Evidence: eval_loss 2.31 with 55% token accuracy is consistent with generic
language modeling of long opportunity texts, and generation showed no
section structure.

**Fix:** pass the raw `{"prompt", "completion"}` text dataset to SFTTrainer
(it performs its own tokenization, EOS handling, and completion-only
masking). Retrain queued as the next run.

**Provenance note:** the VM manifest for this run was nearly lost because the
session stopped before the manifest download; the session script now archives
manifests together with the model. The training loss (2.31) survived in the
downloaded manifest.

**Lesson:** the eval_loss that "looked fine" (2.31 < ln(vocab)) was measuring
the wrong thing — full-sequence LM loss on opportunity text. Always pair
training loss with the task-level metric (here: does the generation follow
the section format?) before believing a run worked.
