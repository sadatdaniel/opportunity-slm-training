# Run: classifier_20260924_213430 — first real classifier experiment

**What changed / why:** First true training run of the Supra-Classifier on
`classifier_dataset_v1` (129 train / 16 val / 17 test, silver+gold tiers),
executed on a free Colab T4 through the WSL + colab-cli workflow. Purpose:
measure whether fine-tuning beats the untouched base model on the frozen
test split — the brief's step-7 proof of concept.

**Hardware / runtime:** Tesla T4 (15.6GB), torch 2.14.0+cu130,
transformers 5.17.0, python 3.13 — **92.4 seconds** for 3 epochs. Full
manifest: `experiments/manifests/classifier_20260924_213430.yaml`.

| metric | trained v0.1.0 | zero-shot base baseline |

| accuracy | **17.6%** | 5.9% (below 8.3% random) |
| macro F1 | 0.080 | 0.011 |
| median latency | ~90 ms (T4, measured locally ~1100 ms CPU) | ~18,000 ms CPU |
| ECE (raw) | 0.210 | — |

Full JSON: `reports/classifier_eval_20260924_215221.json`.

## Interpretation (honest read)

1. **Fine-tuning works**: 3x the zero-shot baseline accuracy, which itself
   sits below random — the untouched base model has no decision ability on
   this task, as the System-One design predicted.
2. **Absolute numbers are weak** — 17.6% vs 8.3% random with 129 training
   examples is a learning signal, not a model. This matches the brief's
   expectation: scale data only as measured gains justify (300 → 750 → …).
3. **Calibration matters immediately**: raw ECE 0.21 → 0.07 after temperature
   scaling (T=7.86 = severe overconfidence, typical of small-data fine-tunes).
4. **Zero-shot criterion scoring is CPU-impractical** (18 s/record) — on T4 it
   is the reference mechanism, not the production path.
5. The 17-example test set is too small to resolve class-level claims; per-class
   numbers in the JSON are directional only.

## What failed

  returns logits, not just probabilities).
